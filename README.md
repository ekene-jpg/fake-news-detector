# Fake News Detection System (Flask + scikit-learn)

Implements the design in Chapter 3: text cleaning → TF-IDF (max_features=5000)
→ Logistic Regression → Flask web app → SQLite `Prediction_History` log.

## 1. Install dependencies

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python -m nltk.downloader stopwords
```

## 2. Get the real dataset (important — replace the demo data)

This project ships with `data/news_dataset.csv`, a **synthetic 800-row demo
dataset** generated by `data/make_demo_dataset.py`, just so you can run the
full pipeline immediately. It is NOT the dataset your chapter cites — swap
it out before you write up results or submit:

1. Download the **Kaggle "Fake and Real News Dataset"** (search that name
   on kaggle.com, or use the Kaggle API: `kaggle datasets download -d
   clmentbisaillon/fake-and-real-news-dataset`).
2. It comes as two files, `Fake.csv` and `True.csv`, each with columns
   `title, text, subject, date`.
3. Combine them into the single-file format this project expects:

```python
import pandas as pd
fake = pd.read_csv("Fake.csv"); fake["label"] = 0
real = pd.read_csv("True.csv"); real["label"] = 1
df = pd.concat([fake, real]).sample(frac=1, random_state=42).reset_index(drop=True)
df.to_csv("data/news_dataset.csv", index=False)
```

That reproduces the 44,898-row / 23,481-fake / 21,417-real composition
described in section 3.4.

## 2.5. Set up the free Google Fact Check API (optional but recommended)

The app cross-checks every analysis against real published fact-checks
(PolitiFact, Snopes, FactCheck.org, Reuters, AFP, and others) via Google's
Fact Check Tools API — a free aggregator of ClaimReview data.

1. Go to **console.cloud.google.com** → create or select a project.
2. **APIs & Services → Library** → search "Fact Check Tools API" → Enable.
3. **APIs & Services → Credentials** → Create Credentials → API key.
4. Set it as an environment variable before running the app:

```bash
export GOOGLE_FACTCHECK_API_KEY="your-key-here"   # Windows: set GOOGLE_FACTCHECK_API_KEY=your-key-here
```

If this isn't set, the app still works fine — it just shows "Fact-check
lookup unavailable" and falls back to the ML model's own prediction.

When a matching claim **has** been fact-checked, its published rating
takes precedence over the ML model's prediction (a real verdict from a
professional fact-checker is more reliable than inferred text patterns).
When nothing matches, that's shown honestly as "not reviewed yet" — not
as "confirmed true."

## 3. Train the model

```bash
python train_model.py
```

Prints accuracy, precision, recall, F1, and a confusion matrix (section
3.15), then saves `model/model.pkl` and `model/vectorizer.pkl`.

**Note on numbers:** the demo dataset is templated and trivially separable,
so it trains to 100% — that just proves the pipeline runs, not real-world
performance. On the actual Kaggle dataset, this exact pipeline (TF-IDF +
Logistic Regression) typically lands around 92–96% accuracy in published
results — expect something in that range, not 100%, and report whatever
you actually measure.

## 4. Initialize the database

```bash
python init_db.py
```

Creates `news_detection.db` with `News_Dataset` (populated from your
training CSV) and an empty `Prediction_History` (section 3.12).

## 5. Run the app

```bash
python app.py
```

Open **http://127.0.0.1:5000** in a browser.

### Testing on your phone (same Wi-Fi)

The app already binds to `0.0.0.0`. Find your computer's local IP
(`ipconfig` on Windows, `ifconfig` or `ip addr` on Mac/Linux — look for
something like `192.168.x.x`), then on your phone's browser (same Wi-Fi
network) visit `http://<that-ip>:5000`.

## 6. Deploying so it's reachable from anywhere

Flask needs a running Python process — **this can't go on Netlify**
(static hosting only). Simple free/cheap options that support Flask:

- **Render.com** — connect your GitHub repo, set start command
  `gunicorn app:app`, add a free web service.
- **Railway.app** — similar, one-click deploy from GitHub.
- **PythonAnywhere** — free tier, good for student projects, has a
  web-based file uploader if you don't want to use git.

Whichever you pick, make sure `model/model.pkl` and `model/vectorizer.pkl`
are included in the deploy (either commit them, or run `train_model.py`
as part of the build step) — the app has nothing to predict with otherwise.
